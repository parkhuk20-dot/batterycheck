# 요구사항 정의서

기준일: 2026-10-06. 상태 열은 코드와 테스트로 확인한 범위만 적는다. `구현`은 자동 테스트 통과를 뜻하며 실제 사용자 검증·공개 배포와는 별개다.

## 1. 개요

- 프로젝트명: 배터리체크
- 목적: 보조배터리 보유자가 자기 제품에 해당하는 공식 리콜 공지의 조건과 다음 행동을 놓치지 않게 한다.
- 대상 사용자: 보조배터리를 쓰는 대학생(초기), 이후 일반 소비자
- 하지 않는 일: 배터리 내부 상태 진단, 화재 확률·안전 점수 산출, 리콜 대상 확정, 자동 신고

## 2. 기능 요구사항

| ID | 기능 | 설명 | 우선순위 | 상태 |
|---|---|---|---|---|
| FR-01 | 계정 | 가입(개인정보 동의 필수)·로그인·로그아웃, 사용자별 데이터 격리 | Must | 구현 |
| FR-02 | 제품 조건 대조 | 브랜드·모델·판매지역 등을 공식 공지 후보와 대조하고 미확인 조건을 표시 | Must | 구현 |
| FR-03 | AI 안내 도우미 | Claude 에이전트가 공식 자료와 보관함을 도구로 조회해 쉬운 말로 설명 | Must | 구현 · 실제 API 호출 미검증 |
| FR-04 | 근거 검색(RAG) | 저장된 공지·안전 안내에서 관련 문서를 찾아 답변에 출처로 연결 | Must | 구현 |
| FR-05 | 대화 기억 | 계정별 대화를 저장하고 다음 질문에 이전 맥락을 함께 전달 | Must | 구현 |
| FR-06 | 제품 보관함 | 저장, 재확인 이력, 사용자 조치 자기보고, 삭제 | Must | 구현 |
| FR-07 | 위험징후 안내 | 연기·불꽃 등 응답 시 리콜 결과와 무관하게 119 안내 우선 | Must | 구현 |
| FR-08 | 공지 갱신·알림 | 공식 자료 갱신 → 저장 제품 재확인 → 변경 시 앱내 알림(동의 사용자) | Should | 구현 · 정기 실행은 worker 구동 필요 |
| FR-09 | 라벨 사진 인식 | 로컬 OCR로 브랜드·모델 후보 추출, 사용자 확인 후 반영 | Should | 구현 |
| FR-10 | 개인정보 통제 | 내 기록 내려받기, 대화 기록 지우기, 계정·전체 기록 삭제 | Must | 구현 |
| FR-11 | 사용 의견 수집 | 1~5점과 자유 의견을 앱에서 제출 | Should | 구현 |
| FR-12 | 국내 리콜 연동 | Safety Korea 공개 API 연결 | Could | 미구현 · 인증키 승인 필요 |

## 3. 비기능 요구사항

| ID | 항목 | 요구사항 | 확인 방법 |
|---|---|---|---|
| NFR-01 | 근거 표시 | AI 답변에는 참고한 공식 자료 링크를 함께 표시 | `test_assistant.py` |
| NFR-02 | AI 생성 고지 | 모든 AI 답변에 "AI 생성 답변 · 공식 판정 아님" 표시 | 화면 확인 |
| NFR-03 | 동의 기반 전송 | AI 이용에 동의하지 않은 계정의 질문·제품 정보는 외부로 보내지 않음 | `test_nothing_is_sent_without_ai_consent` |
| NFR-04 | 판정 보존 | AI는 규칙 엔진의 상태·다음 행동을 바꾸지 못하고 설명만 함 | 시스템 프롬프트, 도구 설계 |
| NFR-05 | 계정 격리 | 다른 계정의 제품·대화가 도구 결과나 대화에 섞이지 않음 | `test_agent_uses_tools_cites_sources_and_remembers` |
| NFR-06 | 장애 표시 | AI·공식 API 실패를 성공이나 "안전"으로 바꾸지 않고 실패로 표시 | `test_official.py`, 오류 응답 |
| NFR-07 | 응답 시간 | AI 답변 목표 30초 이내, 프록시 제한 120초 | 실제 호출 후 측정 필요 |
| NFR-08 | 남용 방지 | AI 질문 5분당 10회, 질문 1,000자, 요청 본문 16KB 제한 | `main.py` |
| NFR-09 | 비밀정보 | 비밀번호 PBKDF2 해시, 세션 토큰 해시 저장, API 키는 환경변수 | `test_accounts.py` |
| NFR-10 | 접근성 | 키보드 이동, 포커스 표시, 상태 메시지 `aria-live` | 화면 확인 |

## 4. AI 활용 명세

| 기능 | 기술 요소 | 방식 |
|---|---|---|
| 질문 이해와 도구 선택 | AI Agent | Claude가 `search_official_documents` · `get_my_products` · `check_product` 중 필요한 도구를 스스로 골라 호출하고 결과를 종합 (최대 6단계) |
| 근거 기반 답변 | RAG | 저장된 CPSC 공지와 소방청·산업통상자원부 안전 안내를 검색해 상위 4건을 모델에 전달, 답변에 출처 연결 |
| 맥락 유지 | Long-term Memory | 계정별 대화를 SQLite에 저장하고 최근 20개 메시지를 다음 요청에 포함. 보관함의 제품·조치 이력도 도구로 조회 |
| 공지 변경 추적 | 자동화 워크플로우 | worker가 공개 API 수집 → 저장 제품 재확인 → 변경 감지 → 앱내 알림 생성 (LLM 미사용) |
| 라벨 읽기 | 이미지 입력 | 로컬 OCR(Apple Vision/Tesseract). 생성형 AI가 아니며 사진은 외부로 보내지 않음 |

세부 설계는 [구현 구조](ARCHITECTURE.md#ai-도우미-설계)를 따른다.
