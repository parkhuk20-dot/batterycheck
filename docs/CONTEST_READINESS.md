# 배터리체크 출품 준비와 근거 대응표

기준일: 2026-10-02. 대상은 **2026 AI·디지털 기반 사회문제 해결 챌린지의 서비스 개발 부문**이다. 이 문서는 준비할 증거와 인수 기준이며, 표에 기능이 적혀 있다는 이유로 구현·검증·배포 완료를 뜻하지 않는다. 최종 실행 결과와 제한은 [최종 검증 보고서](../verification/final_report.md)를 기준으로 확인한다. 보고서가 없거나 항목별 증거가 없으면 해당 결과는 미확인이다.

원본 [배터리체크 기획서](../../배터리체크_개선기획서.md)는 보존한다. `../../application/`의 텐트숨 신청 자료는 다른 기획의 과거 자료이므로 배터리체크 접수 실적으로 사용하지 않는다.

## 3. 기능별 완료 판단 기준

아래는 이번 개발 범위와 확인할 증거다. 구현 상태는 최종 보고서의 실제 테스트 결과를 따른다.

| 영역 | 완료를 판단할 조건 | 구분해서 보고할 한계 |
|---|---|---|
| 계정·제품 격리 | 두 계정 사이 목록·상세·수정·삭제·알림 접근 차단, 세션 종료 검증 | 로컬 테스트 통과와 공개 운영 보안 검토는 별도 |
| 라벨 OCR | Mac의 Apple Vision 또는 컨테이너의 Tesseract 실행 결과를 후보로 제시, 사용자 수정·확인, 실패 시 직접 입력 | 사진 품질별 실측 정확도와 OCR 실행 성공은 별도. 설치만으로 실행 성공을 주장하지 않음 |
| 공식 공지 | 실제 공지의 원문·관할·대상 조건·검토 시점·내용 버전을 추적 | 웹 검토 저장 공지와 실시간 API 조회를 구분. 해외 공지는 국내 회수 자격을 보장하지 않음 |
| CPSC 어댑터 | 성공·잘못된 응답·시간 초과·503에 대한 상태 처리 | 개발 중 관찰된 503은 장애 증거이며 연동 성공이 아님 |
| 조건 대조 | 제품 식별 필요·추가 확인 필요·조회 미완료·일치 없음·대상 일치를 구분 | 일부 출처 실패를 전체 조회 완료로 표시하지 않음 |
| 위험징후 | 제품 입력 전에도 긴급 안내, 리콜 결과나 조치 완료 신고가 안내를 해제하지 않음 | 내부 상태·화재확률·안전점수·전문가 검증으로 확대하지 않음 |
| 앱 내 알림 | 동의·해지, 재검사 시 변경 감지, 중복 방지와 갱신 실패 표시 | 앱 내 보관함 알림과 이메일·문자·푸시는 다름. 실제 스케줄러를 실행하지 않으면 자동 상시 감시가 아님 |
| 내보내기·삭제 | 본인 데이터 내보내기, 계정 삭제 후 데이터·세션 접근 종료 확인 | 저장 기간과 운영 백업의 삭제 정책은 실제 배포 환경에 맞춰 확정 |
| 배포 준비 | 빌드·컨테이너 설정·환경변수·볼륨·상태 확인·복구 절차 | 파일 작성, 이미지 빌드, 컨테이너 실행, 공개 URL 접속을 각각 구분 |

공식 자료의 이용조건과 이미지·텍스트 재배포 범위는 사용 출처별로 확인한다. 공지의 브랜드·모델·로트·시리얼 조건은 유사도만으로 확정하지 않는다. 생성형 모델을 실제 호출하지 않았다면 OCR·규칙 기반 설명을 LLM/RAG 실행으로 표기하지 않는다.

| 팀 3~6인, 역할 분담 | 미확정 | 실제 팀원과 담당을 README에 기입 |

## 5. 출품 전 남길 자료

- [최종 검증 보고서](../verification/final_report.md): 실행일·명령·통과/실패·환경·독립 검토·남은 제한.
- [사용자 검증 절차](USER_VALIDATION.md): 동의, 과제, 익명 결과, 피드백 반영.
- [10분 시연 구성](DEMO_SCRIPT.md): 실제 동작·저장 자료·장애 시연을 구분.
- 실제 접수 확인, 공개 배포 URL, 외부 협력 회신, 실제 사용자 결과는 확보 후 별도 연결. 빈 항목은 미확보로 유지.

출품 완료 여부는 코드 완성 여부와 별도로 판단한다. 실제 사용자 실증·공개 배포·공식 접수가 없는 상태에서 대회 준비가 모두 완료됐다고 주장하지 않는다.
