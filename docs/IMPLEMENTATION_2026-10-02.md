FR-01 직접 모델 입력/사용자 확인 → FR-03/04 가상 공지 조건 대조/추가 질문/판단보류 → FR-05 출처 있는 위험징후 안내 → FR-06 가상 후속 조치 흐름 → FR-07 로컬 보관함/재확인 이력 → FR-09 사용자 조치 자기보고/삭제.

이는 **첫 로컬 프로토타입**입니다. 공식 리콜 API를 구현하거나 실제 회수·교환 경로를 연결한 결과는 아닙니다. FR-02 AI 사진 추출, FR-08 신규·변경 알림, 계정·기관 집계는 미구현입니다. 실제 브랜드에 허위 리콜 공지를 만들지 않으며 실제 제품은 조회 미완료로 처리합니다.

Next.js/FastAPI 기획을 유지했습니다. 한 명의 시연에는 설치 없는 SQLite를 사용하고 공용 서비스용 PostgreSQL·인증·작업 큐는 보류했습니다. 기존 패키지 환경을 읽기 전용으로 재사용하고 npm 캐시의 고정 패키지를 오프라인으로 설치했습니다. 빌드/서버는 각 1 worker입니다.

## 판정 계약

| 입력/자료 조건 | 상태 | 확인 범위 |
|---|---|---|
| 모델 확인 불충분/지원 제품군 아님 | 제품 식별 필요 | 사용자 직접 확인 요청 |
| 가상동의+가상브랜드+모델, 공지의 필수 조건 모두 일치 | 리콜 대상 일치 | 가상 공지에 대한 소프트웨어 대조 |
| 필수 조건 누락 또는 미검토 공지 | 추가 확인 필요 | 질문/미검토 조건 표시 |
| 확인한 입력으로 가상 집합 전체 대조 완료, 조건 불일치/일치 공지 없음 | 조회 범위에서 일치 없음 | 가상 집합에 한정, 안전 보증 없음 |
| 실제 제품/API 미연결, 자료 누락·오류·장애·만료 | 조회 미완료 | 출처 상태와 마지막 자료 시각 표시 |

조건별 일치/불일치/미확인을 보존하고 날짜 파싱 오류는 422로 처리합니다. 모델 접미사·lot 앞자리 0을 없애지 않습니다. 제조일 시작/종료 포함, 월만 아는 제조일·미래/불가능 날짜를 거절합니다. 빈 필수 조건과 다른 조건의 불일치가 함께 있어도 미확인 정보를 음성 판정으로 숨기지 않습니다. 만료/실패 때 가상 후보의 조건 근거는 보이지만 현재 확정 결과는 조회 미완료입니다. 과거 결과는 별도 이력으로 보존하고 현재 결과로 재사용하지 않습니다.
