# 발표 자료 개요

슬라이드로 옮길 내용의 뼈대다. `[ ]`로 표시한 칸은 실제 결과가 나온 뒤 채운다. 시연 진행 순서는 [시연 구성](DEMO_SCRIPT.md)을 따른다.

## 1. 문제 정의와 해결 과정

- 문제: 리콜 공지는 흩어져 있고 조건이 복잡해, 내 제품이 해당하는지와 다음에 할 일을 알기 어렵다.
- 대상: 보조배터리를 쓰는 대학생.
- 해결 흐름: 제품 등록 → 공식 공지 조건 대조 → AI 도우미에게 질문 → 보관함 저장 → 공지 변경 시 알림.
- 범위 제한: 미국 CPSC 공지 일부만 대조한다. 국내 Safety Korea는 미연결. 리콜 대상을 확정하지 않는다.

## 2. AI 활용 방식과 기술적 의사결정

| 결정 | 선택 | 근거 |
|---|---|---|
| AI의 역할 | 설명과 안내. 판정은 규칙 엔진 | 틀린 "안전합니다" 한 마디의 비용이 크다 |
| 에이전트 구조 | 단일 에이전트 + 도구 3개 | 질문 유형이 다양하지만 도구 수가 적어 다중 에이전트가 필요 없다 |
| RAG 검색 | 토큰 겹침 검색 | 문서가 수십 건, 식별자(모델명) 정확 일치가 중요. 벡터 DB는 자료가 늘면 도입 |
| 기억 | SQLite에 계정별 대화 저장, 최근 20개 재전송 | 별도 인프라 없이 계정 삭제와 함께 지워진다 |
| 모델 | GPT 계열 (코디세이 게이트웨이, 도구 사용) | 과정에서 제공하는 API·토큰 사용, 도구 호출 지원 |
| 개인정보 | AI 이용 별도 동의, 사진 미전송 | 가입 동의와 외부 전송 동의를 분리 |

시연: 보관함에 제품을 넣고 "내 제품에 확인할 게 있나요?"를 묻는다 → 도구 호출 → 출처가 붙은 답변 → 다음 질문에서 이전 맥락 유지.
